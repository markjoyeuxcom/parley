Three axes of variation. One is open.

Parley lets a session vary along three dimensions. Only the first was built as an extension seam; the other two are compiled into the binary.

Who argues — personas open

A SQLite table with full CRUD, built-ins that upsert on every boot, inline editing in the composer, and save-as-preset. A properly built seam — and the only one.

What shape the work takes — formats closed

Six workflows in a Go map. Each is four prompt strings and a section list — pure content — yet adding one needs a recompile and a release.

Who runs it — agents closed twice

A fixed-size two-element array, role slots literally named a and b, and modulo-2 alternation. The frontend agrees: the provider name is a hardcoded two-member union that keys the model list and the colour system.

You wrote the same engine twice

This is the finding the first revision under-called. Parley has two independent state machines that do structurally identical work, and neither knows it.

The debate loop

orchestrator.go — loop()
  1. alternate turns × N
  2. gate: referee question
  3. slot A drafts the record
  4. slot B signs or dissents
  5. slot A corrects, bounded ×2
  6. slot A scores on a fixed rubric

The work-plan chain

workplan.go — runPlanning → runMilestone
  1. planner drafts
  2. gate: clarification
  3. auditor reviews
  4. planner disposes findings
  5. gate: human approval
  6. executor writes, checks run, reviewer signs

Both are the same five operations: pick a participant, build a prompt from prior artifacts, run it under an access mode with a timeout, assert something about the output, then either gate on a human or advance. The only real differences are which prompts, which participant, and where the gates sit — all of it data.

The duplication is measurable. Seventeen ad-hoc broadcast event types (turn_started, synthesis_started, countersign_started, correction_started, diff_started, work_plan_status …) that all mean "a stage changed state." Six hand-rolled output validators — convergence markers, referee questions, score cards, clarification requests, milestone counts, the REVIEW: PASS prefix — each a different spelling of "assert something about what the model returned."

And artifacts is keyed PRIMARY KEY (debate_id, kind), so re-running a stage overwrites its predecessor. That is why appending an execution log has to read the old row, concatenate a separator, and write the whole thing back. Stage history is not modelled; it is string surgery. 

// One engine. A session is participants + a protocol; a protocol is stages.

Session
  participants  []Participant   // N, not 2 — provider, model, effort, stance
  protocol      ProtocolVersion // pinned at start; edits never touch live runs
  state         stage cursor, artifacts, open gate

Stage
  actor      one | each | selector   // "each participant", "everyone but the author"
  access     none | read | plan | write
  inputs     which prior artifacts feed the prompt
  prompt     template
  produces   artifact kind
  contract   marker | sections | dimensions | first-line   // declared, not regex-by-hand
  gate       none | human | conditional
  next       stage id, possibly branching

Today's product becomes two seeded protocol documents. Everything on the roadmap — three-way debates, review panels, a dedicated judge, test-gap analysis, incident retros, tournament brackets, self-repair loops — becomes a protocol someone writes, not a release someone ships.

The rebuild

Five phases. The left edge marks blast radius, not permission: green is contained, amber crosses layers, ember deliberately breaks a contract other code depends on.

Phase 1

Participants replace slots

First, not last. If the a/b contract is going to break anyway, break it before building anything on top of it.

N participants

breaks the closing contract effort L foundational

A session_participants table replaces the paired a/b columns. The array becomes a slice, slots become indices, %2 becomes %n. Storage is already halfway there — sessions are keyed by an arbitrary slot string with a legacy provider fallback, so existing runs migrate as index 0 and 1.

The closing sequence is what genuinely has to be redesigned, and it is the reason this phase is large: slot A drafts, slot B countersigns, slot A scores has no meaning with three participants. Replace it with role selectors — the author, everyone but the author, a designated scorer — which is exactly the vocabulary Phase 2 needs anyway.

Unlocks Three-way debate, review panels, an odd-numbered jury with majority verdicts, a dedicated synthesist who never argues.

Phase 2

One stage engine

Collapse the debate loop and the work-plan chain into a single runner. No behaviour change — this phase ships identical output.

The runner, and today's pipelines as seeded protocols

replaces both state machines effort L depends on 1

One loop: resolve actor → assemble prompt from declared inputs → send under the stage's access mode and timeout → validate the contract → persist an artifact → broadcast → evaluate the gate → advance. Both existing pipelines become protocol documents seeded exactly like built-in personas.

The acceptance test is unusually clean, and it already exists. Your mock pipeline tests drive a full session end to end with canned agents and assert the artifacts that come out. Run them against the new engine and require byte-identical results before deleting the old code.

Unlocks Every subsequent feature is written once instead of twice. Seventeen event types collapse to four. Six validators collapse to a declared contract type.

Artifacts get history

schema migration effort M

Key artifacts by session, stage, and iteration rather than by kind. The concatenation hack disappears, re-running a stage stops destroying its predecessor, and the transcript gains a real revision history.

Unlocks Diffing a corrected report against its draft. Seeing which audit finding changed which plan section. Retrying one stage without losing what it replaced.

Phase 3

Protocols become documents

With one engine reading declarative stages, the entire seam-A section of the survey becomes a single feature.

Authoring, versioning, sharing

contained effort M depends on 2

A protocols table with versioned rows, seeded built-ins upserted by name, full CRUD including PATCH, and an editor. Versioning is not optional: a running session must pin the version it started with, or editing a protocol corrupts live work.

Formats, rubrics, work-plan kinds, and memory kinds all collapse into this — they were only ever separate because they were separate Go maps.

Unlocks Four of the seven closed seams close at once. Protocols become shareable files — a library of session designs, not a changelog of releases.

Editability everywhere

contained effort S–M

PATCH for personas, protocols, memory entries, project names, session topics, and dispositions. Small, and it removes the single widest-reach finding in the survey.

Unlocks The app stops being write-once. Authoring protocols becomes livable rather than an archive of typos you can only delete.

Phase 4

Make the work visible and addressable

Independent of the engine work, and much cheaper once stages are uniform.

Usage accounting, full-text search, scoped memory, CLI parity

crosses layers effort M each

Token and cost capture per stage — verify what each CLI actually reports before designing the schema; Claude's result event carries usage, Codex needs checking. An FTS5 table over turns and artifacts behind a search endpoint. A scope column on memory so repository sessions stop being excluded from distillation entirely. And show, plan, approve, export, search on the CLI — trivial once every stage speaks one vocabulary.

Unlocks Knowing which protocols and model pairings earn their cost. An archive that answers "where did we decide this?". Repository reviews that accumulate knowledge instead of starting cold.

Phase 5

Scale hygiene

Pull forward the moment the archive passes a few hundred runs, or as soon as Phase 4 adds a second thing to poll.

Indexes, pagination, delta fetch, configurable bounds

contained effort S–M

Indexes on every session_id foreign key. LIMIT and offset on the run list with the turn count denormalised. A since-index parameter so the desktop poll fetches new stages instead of the whole session every second. Timeouts and concurrency move from constants to configuration — bounded, with sane maxima, not unlimited.

Unlocks Thousands of runs stay as responsive as twenty.

What stays fixed

The access ladder is a safety property, not a product limitation

AccessNone / Read / Plan / Write maps to real sandbox flags — Claude's empty --tools, safe mode with slash commands disabled, Codex's read-only sandbox. Those are the reason attaching a repository to a session is something you can do without thinking about it.

A user-authored protocol may request an access level. It must never define one. The binding from access level to CLI flags stays in Go, stays non-overridable from data, and write access stays behind an explicit human approval gate that a protocol cannot skip. Otherwise "user-editable protocols" quietly becomes "user-editable arbitrary code execution in your repository," and the feature that makes Parley safe to point at real work is the one the rewrite removed.

Everything else in this document is negotiable. This is not, and it is worth building the protocol schema so that it is structurally impossible to express — the access field enumerated, never free text.

Start here

The first branch

  1. Pin the regression harness first: make the mock pipeline tests assert full artifact output, so they can prove the rewrite is behaviour-preserving.
  2. Add session_participants; migrate existing runs to index 0 and 1; keep the legacy provider-keyed session fallback untouched.
  3. Replace the array with a slice and %2 with %n. Leave the closing sequence hardcoded for now — it still passes on two participants.
  4. Redesign the closing sequence around role selectors (the author, everyone but the author, the scorer). This is the real work of Phase 1.
  5. Only then start Phase 2. The stage engine wants those selectors to already exist.
